How it's enforced, in configuration and code rather than instructions:
1. Each subagent's `tools:` list in `.claude/agents/*.md` grants only its tools. The withheld storage and retrieval tools are also listed under `disallowedTools`.
2. `.claude/settings.json` `permissions.deny` blocks `Read` and `Edit` of `.memory/reference/lessons/**`, `.memory/storage.db*`, `.memory/storage-audit.log` and `//memory/**`, plus `Bash(sqlite3 *)`.
3. Claude's deny rules don't cover MCP tools, so `mcp/coursetools_server.py` refuses the same paths in `file_read` and `file_write`, and `codebase_search` skips them.
4. The retrieval server clamps every search to `RETRIEVAL_MAX_CEILING` (default `internal`, set in the container env). A caller asking for `confidential` gets internal at most, and the keyword fallback uses the same clamped value.
5. The storage server refuses confidential and secret writes.

## 6. Deliberate deviation: network

The lesson runs agent containers on `docker network create --internal agent-internal`. I created it and tested it: `curl localhost:8000` returned 200 and `curl https://example.com` failed with "Could not resolve host", as intended. But that network also blocks the Claude API, so Claude Code can't work there (`claude -p "say hi"` got no reply). On Docker's normal network the same command answered normally.

What I did instead:
- Agent sessions run on the normal network.
- Both MCP servers bind to 127.0.0.1 inside the container and no ports are published (no `-p`), so only processes in that container can reach them.
- Builds, validation runs and the clamp test ran on `--network none`. Loopback worked there, so the servers were reachable, and the baked-in model meant nothing had to download.
- No API key is passed into agent containers. Claude signs in through the `claude-auth` volume.

## 7. Known gaps and next steps

1. **Q4 below threshold.** Correct doc first at 0.573, below 0.65. Known gap. Next: corpus fix (plain-English sentence in the golden-trace doc), rerun the whole set.
2. **Agent queries never matched by vector.** All 14 live-run results were keyword matches. The planner and fence-reviewer wrote keyword strings, not questions, so nothing cleared 0.65. Next: try hybrid retrieval in the server (always merge the vector top-k with the keyword hits, each labelled), and have the roles phrase queries as questions.
3. **Keyword fallback is noisy.** It ORs every word, stopwords included. Next: drop stopwords in `fts_query` and set a minimum match before returning a keyword hit.
4. **`read_entry` skips the ceiling clamp.** It fetches by ID with no ceiling. It's safe today only because no role holds `read_entry`. Next: add the same clamp to `read_entry` and `list_entries` in the storage server, and deny the unused storage tools in `settings.json`.
5. **`calling_role` is self-reported.** The storage server records whatever role the caller passes. The audit line is trustworthy because only the implementer holds `write_entry`, not because the server checks. Next: a per-role allow-list in the storage server, like coursetools has.
6. **Main-session limits are instruction-only.** Claude Code doesn't restrict the main session's tools from a definition file. The restart check showed the main session following `CLAUDE.md` and asking for a waiver, but nothing technically stopped it.
7. **Bash deny rules are best-effort.** `Bash(sqlite3 *)` won't catch `python -c` opening the file. Only the tester and demo-verifier have Bash as subagents.
8. **Q3 didn't test the fallback.** It passed by vector. Q4 and Q5 exercised the fallback instead. A future keyword query should use a token that doesn't also match by meaning.
