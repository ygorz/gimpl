### Decisions Made So Far

1. **Callers:** there are 12 callers in Heretic.
   - 10 are pickup cases in `P_TouchSpecialThing`: `p_inter.c:654, 661, 668, 675, 682, 689, 696, 703, 710, 717`. They're reached from `PIT_CheckThing` at `p_map.c:434`.
   - 2 are cheat calls in `CheatArtifact3Func`: `sb_bar.c:1200, 1216`, both with `mo = NULL`.
   - The Hexen `P_GiveArtifact` (`src/hexen/p_inter.c:789`) is out of scope.
2. **Fields:**
   - `inventory[i].type`: read 430, written 437.
   - `inventory[i].count`: read 442, written 436 and 446.
   - `inventorySlotNum`: read 430 and 434, written 438.
   - `artifactCount`: read 448, written 452.
   - `readyArtifact`: written 450.
   - `itemcount`: written 455.
   - `mo->flags` with `MF_COUNTITEM` (`doomdef.h:240`): read 453 after a NULL check.
   - The function touches no globals, no RNG and no thinker list.
3. **Cheat callers can't run in a demo.** Cheats come from live key events through `G_Responder` → `SB_Responder` → `HandleCheats` (`g_game.c:1021`, `sb_bar.c:995–1033`). Demo playback uses ticcmds (`g_game.c:1176–1177`), not key events.
4. **Demo reachability is "Not confirmed" for DEMO1, DEMO2 and DEMO3.** It depends on the demo lump contents, and no instrumented run has been done. Confirming it needs an operator action: a counter or a gdb breakpoint on `p_inter.c:425`.
5. **What stays in C:** all callers, `P_SetDormantArtifact` (which reads `deathmatch` and calls `P_SetMobjState` and `S_StartSound`), `P_SetMessage`, `CheatArtifact3Func`/`HandleCheats` and their globals, and every other user of the inventory fields. The fence is quoted word for word in the spec.
6. **Rust signature is a proposal:** `extern "C"`, with `*mut player_t`, `artitype_t`, `*const mobj_t` that may be NULL, returning `boolean`. The repo has no `Cargo.toml` or `*.rs` files, so there are no existing FFI conventions to follow.
7. **Porting notes recorded in the spec:**
   - The slot loop reads `inventory[i].type` before it checks the bound.
   - `P_PlayerRemoveArtifact` (`p_user.c:836–848`) leaves a stale entry past the end of the list. `P_GiveArtifact` reads it, then overwrites it, so the result is unchanged.
   - Nothing checks against `NUMINVENTORYSLOTS` (14). It can't overflow because there are only 10 artifact types. The port may add a `debug_assert!` at most and must never silently cap.
   - The count cap is an inline literal `16` with a `>=` test.
8. **DEMO1** stays a **pinned** check: `scripts/demo1-check.sh` at 4227 gametics.
9. **DEMO3** was added as **not yet pinned** at 2582 gametics (`-timedemo demo3`).
   - The number comes from the operator. In the repo it appears only in `docs/context/2.2-pre-session-plan.md:40` and `docs/context/2.2-technique-plan.md:21`, with no run log.
   - No script runs DEMO3, because `demo1-check.sh:49` hard-codes `demo1`. The operator runs it by hand.
   - A mismatch should be reported and investigated, but it doesn't block the port.
10. **DEMO2** stays in the map as not confirmed. It's not in the verification plan, and the repo has no recorded tic count for it.
